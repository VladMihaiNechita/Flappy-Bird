FLAPPY BIRD AGENTS - METHOD EXPLANATION
=======================================

1. Observation modes
--------------------

No agent reads screen pixels. Four variants use the compact observation mode
(use_lidar=False), and the LIDAR Double DQN uses the 180-sensor mode
(use_lidar=True).

The 12 values are:

  - Three values for each of three pipes:
      1. Horizontal pipe position
      2. Top of the opening
      3. Bottom of the opening

  - Bird vertical position
  - Bird vertical velocity
  - Bird rotation

The values are normalized. The vertical velocity makes this observation a much
better learning state than a single LIDAR frame, which does not explicitly say
whether the bird is moving up or down.

game_env.py contains the shared environment setup. Training runs without a game
window for speed; play mode creates a visible window.

The LIDAR mode contains 180 normalized distances from the bird to obstacles.
One scan does not explicitly contain vertical velocity. The improved LIDAR
agent converts distance to proximity and supplies explicit changes between
successive scans. Tiny floating-point values above the declared maximum are
clipped safely.


2. Agent summary
----------------

This project contains five agent variants:

  1. Original PPO (main.py)
     A neural-network reinforcement-learning baseline trained from scratch.

  2. Improved PPO (ppo_agent.py)
     A PPO policy first taught to imitate the planner, then fine-tuned with
     reinforcement learning. It is not a from-scratch agent.

  3. Model-based planner (compact_planner.py and planner_agent.py)
     A search algorithm that uses the known game physics. It does not learn.

  4. Scratch Double DQN (dqn_agent.py)
     A new neural-network agent that learns only through game interaction. Its
     random exploration is biased toward action 0 (idle), instead of using the
     poor 50/50 idle/flap distribution.

  5. LIDAR scratch Double DQN (lidar_dqn_agent.py)
     A convolutional Double DQN that learns from proximity and temporal changes
     in the 180 sensors, without compact features, demonstrations, or physics
     knowledge.


3. Original PPO agent
---------------------

PPO means Proximal Policy Optimization. It learns a policy that directly gives
probabilities for idle and flap, plus a value estimate of how promising the
current situation is.

The original agent in main.py uses the raw 12 values and two hidden layers of
128 neurons. Eight games run in parallel during training. A shaped reward gives
positive feedback for surviving and passing a pipe, negative feedback for
dying, and a small hint that favors being close to the upcoming gap center.

This is an on-policy method: after collecting a batch of recent experience, PPO
updates the policy and then collects new experience. Its clipping rule prevents
individual updates from changing the policy too abruptly.

Saved model:

  models/compact_ppo.zip

Measured result over the comparison seeds:

  Mean score:    5.30
  Median score:  4
  Maximum score: 28

Commands:

  python main.py train --steps 500000
  python main.py evaluate --episodes 50
  python main.py play


4. Improved PPO agent
---------------------

The improved agent in ppo_agent.py uses a larger 256-by-256 neural network and
has two training stages:

  1. The planner generates example observations and actions.
  2. Supervised imitation learning teaches PPO to copy those actions.
  3. PPO reinforcement learning then fine-tunes the copied policy using actual
     game rewards.

Class weighting is used during imitation because idle occurs much more often
than flap. Without it, a network could appear accurate by predicting idle too
often. The intermediate imitation model and final model are saved separately.

Saved models:

  models/compact_ppo_pretrained.zip
  models/compact_ppo_improved.zip

Measured result over the same 50 comparison seeds:

  Mean score:    6.76
  Median score:  4
  Maximum score: 38

Commands:

  python ppo_agent.py train --steps 500000
  python ppo_agent.py evaluate --episodes 50 --score-limit 200
  python ppo_agent.py play


5. Model-based planner agent
----------------------------

The high-scoring planner is not a neural network. It reads the 12 values and
simulates possible future flap sequences with the exact game rules:

  - Action 0 means idle.
  - Action 1 means flap.
  - A flap sets vertical velocity to -9.
  - Otherwise gravity adds 1, up to a falling speed of 10.
  - The bird moves by its updated velocity.
  - Pipes move left by 4 pixels per step.

At every simulated frame, trajectories that hit the top, ground, or a pipe are
discarded. The search keeps the best 200 remaining states rather than every
possible action sequence. This is called beam search.

Safe trajectories are ranked by gap alignment, vertical speed, and unnecessary
flaps. The target within the current gap is adjusted toward the following gap,
which helps with difficult height transitions. The planner replans when it runs
out of planned actions or a previously hidden pipe becomes visible.

If no safe search result exists, a small emergency controller aims for the next
gap center and flaps only when the bird is low and descending.

The planner performs best because the game is deterministic, its physics are
known, and it has only two actions. Its trade-off is computation: a wider search
is safer but slower.

Verified over five unseen seeds with a score limit of 1,100:

  Mean score:          810.60
  Median score:       1100
  Minimum score:       176
  Maximum score:      1100
  Runs reaching 1100:  60 percent

Commands:

  python planner_agent.py
  python planner_agent.py evaluate --episodes 5 --score-limit 1100


6. Scratch Double DQN agent
---------------------------

The new agent in dqn_agent.py learns from an empty replay memory and randomly
initialized neural-network weights. It receives no planner demonstrations and
does not read the physics code.

DQN means Deep Q-Network. For each state, the network estimates two Q-values:

  Q(state, idle)
  Q(state, flap)

The larger value is the action expected to lead to more future reward. The
network has two hidden layers of 256 neurons.

The agent stores transitions in a replay memory containing up to 100,000 game
steps. It learns from random batches of 128 stored transitions. Replay reuses
experience and mixes old and new situations, making DQN more sample-efficient
than learning only from the latest trajectory.

This implementation uses Double DQN. The current network selects the best next
action, while a slower target network evaluates that action. Separating these
two jobs reduces the optimistic value errors that can occur in ordinary DQN.
The target network is refreshed every 2,000 steps.


7. DQN observation preparation and reward
-----------------------------------------

The observation remains exactly 12 numbers, but dqn_agent.py makes it easier
for a small network to learn:

  - It puts the upcoming pipe first.
  - Pipe horizontal positions become distances relative to the bird.
  - Gap boundaries become vertical distances relative to the bird center.
  - Bird position, vertical velocity, and rotation remain present.

This representation means similar situations look similar even when the pipe
array rotates or the whole scene is at another screen position.

The DQN training reward is:

  - Death: -5
  - Passing a pipe: +5
  - Other steps: 0.1 minus the distance from a useful point in the next gap

The score used for final evaluation is still the real number of passed pipes.
Reward shaping only supplies denser feedback while learning.


8. Biased DQN exploration
-------------------------

At the start of training, DQN explores often. Instead of choosing randomly with
a 50/50 split, its random actions use a configurable flap probability. For
example, 20 percent means:

  - 80 percent of random actions are idle.
  - 20 percent of random actions are flap.

This bias is used both before learning begins and during epsilon exploration.
The probability of taking a random action decreases from 100 percent to 5
percent during the first half of training. After that, 5 percent exploration is
retained. The learned policy is used without randomness during evaluation.

Three independent agents were trained from scratch for 300,000 steps each and
tested on the same 30 unseen seeds with a score limit of 200:

  Random idle/flap     Mean    Median    Min    Max
  ----------------    ------   ------    ---    ---
  90% / 10%            35.33    24.0      4      97
  80% / 20%            37.90    28.5      2     137
  70% / 30%             3.57     2.0      0      19

The 80/20 exploration mix won. A larger final test of that model over 100 unseen
seeds produced:

  Mean score:    33.73
  Median score: 25
  Minimum score: 2
  Maximum score: 158

The 70/30 result shows that excessive random flapping can make exploration much
less useful. The result also supports avoiding 50/50, which would be even more
aggressive. Because neural-network training is stochastic, exact results can
vary between new training runs.

Saved models:

  models/dqn_scratch_flap_10.zip
  models/dqn_scratch_flap_20.zip
  models/dqn_scratch_flap_30.zip
  models/dqn_scratch_best.zip       (copy of the winning 80/20 model)

Commands:

  Play the best DQN:
    python dqn_agent.py play

  Evaluate it:
    python dqn_agent.py evaluate --episodes 100 --score-limit 200

  Repeat all three scratch experiments:
    python dqn_agent.py experiment --flap-probabilities 0.1 0.2 0.3 --steps 300000

  Train only a fresh 80/20 agent:
    python dqn_agent.py train --flap-probability 0.2 --steps 300000 --fresh

  Continue training the existing 80/20 agent:
    python dqn_agent.py train --flap-probability 0.2 --steps 300000


9. LIDAR scratch Double DQN agent
--------------------------------

The agent in lidar_dqn_agent.py starts with random neural-network weights and
an empty replay memory. Its only observations are the 180 LIDAR distances.

A single scan cannot distinguish some states where the bird is at the same
position but moving in opposite directions. The accepted preprocessing converts
distance to proximity and supplies an observation with shape (4, 180):

  - Current proximity: 1 minus current distance
  - Current proximity minus previous proximity
  - Previous proximity minus the proximity before it
  - The preceding proximity difference

This retains only LIDAR-derived information while making motion explicit.

The feature extractor treats the rays as a one-dimensional signal:

  - Convolution with 32 channels
  - Convolution with 64 channels
  - A second convolution with 64 channels
  - Projection to 256 learned features
  - A 256-neuron Q-value layer for idle and flap

Convolutions are useful because neighboring rays usually describe neighboring
parts of the same obstacle. The agent then uses the same Double DQN target rule
as the compact scratch agent.

Training configuration:

  - 500,000 collected transitions from random initial weights
  - Eight parallel headless game environments
  - Replay memory of 50,000 transitions
  - Batch size of 128
  - Learning rate of 0.0002
  - Learning begins after 5,000 transitions
  - Target-network update every 2,000 transitions
  - Discount factor of 0.99
  - Three-step Double DQN targets
  - Random flap trigger probability of 20 percent
  - Two forced idle frames after each exploratory flap
  - Epsilon decreases from 100 percent to 5 percent
  - Score evaluation and checkpoint selection every 50,000 transitions

The training reward remains -5 for collision and +5 for passing a pipe. At
other steps, the agent keeps the environment's LIDAR reward. The tested
clearance-shaping reward was rejected, so no compact pipe positions or custom
clearance potential are used by the final agent.

Incremental screening used identical training seeds, 150,000 transitions, ten
checkpoint-validation seeds, and twenty held-out screening seeds. An
improvement was kept only when it improved median score, or improved mean by at
least 10 percent without reducing median.

  Candidate                         Mean   Median   Maximum   Decision
  -------------------------------  ------  ------   -------   --------
  Raw four-frame baseline            4.80     3.0       12    Baseline
  Proximity plus temporal changes     9.45     6.0       36    Keep
  Add dueling head                    9.30     6.0       28    Reject
  Add prioritized replay              3.70     2.5        9    Reject
  Add three-step returns              10.00    10.0       26    Keep
  Structured exploration, 20%         13.55    13.5       31    Keep
  Structured exploration, 10%          6.45     5.5       14    Reject
  Structured exploration, 15%         10.30     8.0       35    Reject
  Add LIDAR clearance shaping           9.15     6.0       48    Reject

The recurrent candidate was stopped after its 30,000-step checkpoint. It scored
mean 0.8 and median 1 while training about eight times more slowly and
saturating the GPU. This was not enough benefit to justify completing the full
run, so temporal-difference channels were retained.

The accepted configuration was then trained for 500,000 transitions. The
350,000-transition checkpoint was selected because later weights became less
consistent. It scored mean 38.85, median 24, minimum 2, and maximum 186 on the
twenty held-out screening seeds.

The final checkpoint was tested once on 100 entirely fresh seeds:

  Mean score:    42.08
  Median score:  29.5
  Minimum score: 3
  Maximum score: 200

Saved models:

  models/lidar_dqn_scratch.zip       Original baseline
  models/lidar_dqn_improved.zip      Accepted improved agent

Commands:

  python lidar_dqn_agent.py play
  python lidar_dqn_agent.py evaluate --episodes 100 --score-limit 200
  python lidar_dqn_agent.py train --steps 500000 --fresh

The LIDAR agent now exceeds the compact DQN's measured mean, although the tests
use different unseen seed ranges. Both learned agents remain far below the
model-based planner's reliability.


10. Which agent should be used?
-------------------------------

Use the planner when the goal is the highest score and reliable play. Use the
scratch Double DQN when the goal is to study an agent that genuinely learns by
trial and error from efficient state features. Use the LIDAR Double DQN to study
learning from raw range sensors and temporal observations. Use original PPO as
a simple policy-gradient baseline, and use improved PPO to study how expert
demonstrations can help an RL policy.

The learned DQN agents are much stronger than both PPO results, but they do not
meet the planner's mean-above-500 target. Reaching that level with a purely
learned agent would likely require a new improvement beyond the rejected
components in this ablation.
